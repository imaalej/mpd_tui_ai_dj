Does a frame make the rotation readable?

Every frame below is drawn by a port of vibe_cloud.compute_frame — the same Braille grid, the same painter's sort, the same 24-bit colours the TUI panel emits. It is checked, not trusted: 33 poses × 2,880 cells diffed against the Python renderer, 0 dots and 0 glyphs differing. The panel sits on the terminal's real background — #15141b, not a flattering near-black — because the frame's faint end is only meaningful against the ground it is actually drawn on. Drag the panel to orbit it, and switch frames on the right.

Why a frame at all

      
At the default orbit speed 95% of points are frozen in any 60 fps frame,
        and the ones that move jump a whole dot. Nothing subdivides that step — so
        the fix is not more frames, it is giving the eye something fixed to read the
        motion against.

    

    

      
What "lower opacity" means here

      
Braille has no alpha, and eight dots share one cell colour. So a faint line
        is two things: a genuinely dark colour (24-bit can sit just above the
        background; the old 256-cube could not) and stippling — sampling every
        second dot. The frame is also splatted with a negative depth bump, so any
        track in the same cell wins the colour. It can never recolour the data.

    

    

      
The box is ±2σ

      
Not a number picked to look right: the coordinates are z-scored per axis,
        so the box states a fact — most of the library is inside it, and the
        outliers visibly are not. Ticks on the ruled axes are one σ apart.
